# Current architecture

Battle v2 Phase C production integration is implemented locally under [the specification](../../BATTLE-V2-SPEC.md) and [Phase C plan](../../BATTLE-V2-PHASE-C-PLAN.md). [Prior architecture](../../archive/ARCHITECTURE-through-phase-b.md) preserves historical decisions/checks. No deployment has occurred in this session.

## Hosting and authority

One React/TypeScript client and Cloudflare Worker on workers.dev. Workers Free, SQLite-backed `LaboratoryRoom`, `MatchmakingPool` and `GuestLease`, their bindings/namespace identities and existing migration tags remain unchanged. Self-hosted scottjmiller.com/www routing is untouched. Servers own admission, private trays/draw plans, DNA, budgets/cooldowns, switch state, frozen mechanics, clocks, combat seeds/timelines, score, awards, progression and guest ownership. Clients send intentions and render accepted state. No hidden catalogue is imported into the client.

## Storage and compatibility

Room JSON schema is **6**, wire/socket protocol remains **5** (`mm-v5` / `mm-queue-v5`), gameplay/default rules are **0.5.0** and DNA/combat catalogues remain **0.2.0/0.3.0**. Rules 0.4.0 introduced Americas-only new entry; 0.5.0 adds the separate one-second Unleash delay. Numerical DNA/combat calibration and the six-second injection cooldown are unchanged. Additive optional `battlePresentationVersion` and `battlePresentation` snapshots require no breaking protocol bump; existing room credentials and protocol-5 pending intentions/receipts remain usable.

Schema 2/3/4 mechanics/combat migrations retain their existing compatibility boundaries. Schema 5 migrates to 6 with `presentationVersion: null` and `battlePresentation: null`, preserving its current hand, freeze, timeline, deadlines, scores and credentials. A new `startRound` enables `battle-v2-b2`; an old active attempt is never randomly transformed retroactively. Unknown/corrupt versions fail closed. Room/action receipts, private creation mappings, rate windows, allocation journals and fenced guest claims remain in their current SQL tables.

`beginRelease` settles accepted mechanics, freezes the original creature/stats/abilities/attribution and derives one presentation from surviving active IDs. The sole rule mapping is `src/shared/integrated-form.ts`; the server selector uses unbiased server entropy for highest-vote ties and the three arenas. Frozen mechanics and presentation share the existing serialized SQLite room transaction, before any snapshot/ack broadcast. Private persisted audit counts are validated against frozen survivors without entropy on every load. Public snapshots expose chosen family, modifiers, attempt/version, integration interval and arena, never votes/entropy/private hands/tokens/battle seeds. Repeated switches, grace/deadline catch-up, eviction and restart cannot reroll or rescore.

Public completed results expose the same persisted terminal battle for integrated autopsy/session-results presentation. The next attempt clears the previous descriptor/timeline. Private host advancement/replay and public readiness/replacement/regroup timers remain unchanged. Battles already underway finish after disconnect; waiting seats and legacy displays retain their original permissions.

## Entry and recovery

New Quick Play entries use the existing Americas pool. The coordinator rejects a new non-Americas operation before acquiring a claim; an existing owner ticket is checked first, so its retry/resume/cancel/status/admission continues in its original pool. Existing pool identifiers/records and cross-pool guest fences remain valid. No automatic migration or queueing occurs. The UI removes region measurement/selection and new Same-Room/display creation/join controls; private code/link participant entry remains remote. Backend legacy presentation/display APIs are retained for existing credentials/clients, with viewing-only authorization.

Tab room/pending-action storage and browser guest identity storage keep their current keys. Successful entry retires its operation key; failed requests keep it. Recovery/leave uses authenticated ownership and observed claim nonces. New admission never resets a guest or clears a newer claim. Wire validation still rejects extra authoritative fields, unknown actions, missing fences and oversized input; origin and rate checks remain.

## Presentation and audio

Experiment retains the approved modular `Chamber`, shared anchors/pivots, static fallback and bounded 16-texture scene lifetime. Accepted history updates produce one coalesced 800ms fluid/quiver reaction; selection/rejection/replayed or old history is inert. Server-time updates refresh the clock estimate without owning transport. Release uses the existing five seconds: Integrating DNA, reveal, then battle. Loading never adds a delay.

New-attempt briefing uses the registered rival idle silhouette; legacy attempts keep their prior portrait. Production reuses Stage/Sprite, registered grafts, the single effect registry, shared timeline projection, actor-based SVG mirroring and inward defensive shields. It preserves frozen presentation through terminal results while damage is side-specific text. Countdown/final words follow accepted timeline time; production timeout-only winner/draw text waits for the published authoritative RoundResult. Isolated development studies may label their terminal health comparison, but production never substitutes that comparison for a result. Legacy attempts use the prior renderer. A shared CSS module holds runtime styles; preview controls/fixtures remain development-only.

One gesture-unlocked sound engine per device retains mute/volume settings, a limiter, ambient ducking and at most eight voices. Onset derivation suppresses repeated status ticks/refreshes. A per-battle high-water cursor suppresses old cues after clock corrections, sleep, reconnect or skipped frames. Pausing decorative motion does not pause authoritative time or remove captions. Motion/settings/resize do not replace the room socket. Loading failure offers retry with health/controls/captions preserved.

`preloadSample` loads common/rival media during briefing and the selected player/rival/arena at release; its Promise cache is bounded at 28 images. Browser/GPU cache retention is not established by this bound and needs physical-device measurement. Root production theme uses semantic controls, legible labels, keyboard-focusable scroll regions, 44px controls and mobile reflow; fixture selectors/overrides/debug globals never ship.

## Assets and validation

`npm run build` builds Vite then explicitly copies approved runtime derivatives and the New Rocker OFL license. `dist/battle-v2-shipping.json` records shipped hashes/bytes; the production guard verifies them and excludes source masters, provenance, gallery fixtures and development controls. Original masters, prompts, registration and provenance remain under `assets/`; closed review documents/evidence are indexed under `docs/archive/`.

[Current implementation status](../../IMPLEMENTATION-STATUS.md) and [Phase C review](../../BATTLE-V2-PHASE-C-REVIEW.md) list checks actually run and their scope. Worker dry run checks bundling/bindings, local independent clients exercise real SQLite/sockets/alarms/reactivation, and Chrome checks use real production build controls/media. These do not establish deployed account access, physical-phone/Safari/Firefox performance or free-tier capacity. Phase D acceptance and explicit deployment remain separate.

Compatibility note: an already-open pre-update browser tab retains its older UI until reload. Reload adopts the new assets/layout while preserving protocol-5 credentials and pending intentions; the stored descriptor never rerolls. Older active attempts retain legacy presentation even after reload. Updated clients receive the same chosen descriptor/arena; additive wire compatibility does not hot-replace an old JavaScript renderer.


## Approved predeployment refinement — 15 October 2026

[Scope and actual verification](../../PREDEPLOY-REFINEMENT.md). `switchReadyAtMs` is an additive private-controller field derived from the existing persisted `nextInjectionAtMs` and the attempt's rules version. No JSON schema, infrastructure migration, hidden vote or entropy change. Server common action validation retains phase/ownership/deadline checks; injection and switch then enforce separate deadlines. Old 0.2/0.3/0.4 attempts retain six seconds for both; new 0.5.0 rounds require one second for the switch and six between injections. Retrying/reloading never resets these timestamps.

The first-entry native dialog dismisses after three seconds or immediately by button/Escape. Saved room/queue credentials bypass it; the normal app/transport remains mounted. Rehearsal and its queue gate are removed. Successful authenticated leave already clears room/pending keys; only disconnected Connection help exposes local reset. Clipboard copying has accessible feedback and selectable input fallback.

Thirty development-generated specimen illustrations preserve public opaque clue keys and shape/color clues. The follow-up uses thirty short unique appearance-based names, with no visible accession code, long description or rating-like dot row. Screen readers retain morphology clues and tray position; internal IDs and server payloads remain unchanged. Decorative painted inlays carry no quality/power rating. All originals/prompts/history/hashes are retained under `assets/specimens/`; runtime 224px WebP pictures are lazy loaded for the current tray, with original SVG fallback. No trait name/mechanical mapping ships in art filenames or client metadata. `/specimen-gallery` is development-only. Cabin/PT Serif WOFF2 files are official unmodified Google Fonts subsets, locally served with OFL licenses; source TTFs/download stylesheet and hashes remain outside production. Frames/scrollwork/buttons/sliders are original CSS/vector code inspired by references, which are not shipped.

Victorian frames follow [Jacob Filipp’s dual-motif technique](https://jacobfilipp.com/victorian-dual/): original shaded cast-iron/acanthus/tracery vectors, percentage nine-slice fixed corners and complete edge motifs, plus splash-only fixed-cap/doubled-repeat horizontal friezes with widths quantized using CSS `round(down, ...)`. A `border-image-repeat: round` fallback and forced/high-contrast borders preserve content. Original geometry/provenance: `scripts/prepare-victorian-frames.py` and `assets/interface-frames/provenance.json`. Frames never own transport or renderer lifetimes.

The 15 October sculpted-iron style revision retains the frame method and existing dimensions. Vector gradients/highlight paths supply relief without filters or runtime animation; earlier geometric sources are preserved under `assets/interface-frames/history/`. No authoritative or lifecycle behavior changes.

The latest approved refinement removes inner friezes from every non-splash control frame. `InjectionReservoirs.tsx` replaces the old chamber rails with a single locally bundled generated WebP shared by both sides: fixed-proportion cap/base windows and a vertically adaptive straight shaft. A clipped SVG pulse retains the existing 800ms coalesced accepted-injection feedback, hidden under reduced motion; native primitives survive image failure. Gauges are decorative, excluded from accessibility navigation, and carry no dose/progress authority. Reserved layout gutters prevent chamber overlap. No socket, server clock or scene-engine ownership changes. Exact prompts/originals, crop/resize pipeline, hashes and channel/segment registration are under `assets/chamber-reservoir/`.

Client-generated operation/action IDs use `src/client/random-id.ts`: native `crypto.randomUUID()` on capable origins, secure `getRandomValues()` UUID v4 fallback on ordinary LAN HTTP. This supports local phone testing without weakening replay-key entropy or changing persisted IDs, retries or any server-owned random decisions. `tests/lan.browser.mjs` covers actual non-secure-origin startup/private/public flow independently of trusted-localhost checks.
